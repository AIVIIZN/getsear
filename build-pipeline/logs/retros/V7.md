## Release caveats

- Local k6 execution was not possible in this slot: `k6` is not installed and no `DEMO_PASSWORD` / `LOAD_TEST_DEMO_PASSWORD` is present in the shell. The repository's `.github/workflows/load-test.yml` is the correct release-run path because it consumes `LOAD_TEST_DEMO_PASSWORD` from GitHub Actions secrets and uploads `load-tests/summary.json`.
- The DB-kill graceful-degradation demo was not performed locally because this slot has no staging DB kill credentials and production DB disruption is not safe for an autonomous release task. V7.3 chaos coverage validates server resilience under 5% synthetic client faults and latency jitter; true database outage drills should run only against staging.
- V7.5.2 and V7.5.3 remain deferred warning-level React compiler lint debt, not V7 release gates. `npm run lint` exits cleanly with those warnings.

## What worked

- The reliability work now has hard gates instead of narrative confidence: schema drift guard, bundle budget guard, k6 scripts, backup/restore scripts, and route-group error recovery all live in source control.
- Observability is wired through both server and browser paths: structured logs carry request IDs, warn/error logs can reach Sentry, RUM metrics aggregate into the dashboard, and deploys stamp `SENTRY_RELEASE` when configured.
- V7.2 recovered the earlier POS bundle miss: the bundle budget guard now passes under the 200KB gzip target.
