## What worked

- **Parallel worktrees + specialist agents.** Each batch ran 2-5 implementers concurrently in isolated git worktrees against domain-tuned personas. Cycle times were dominated by review/integration, not implementation.
- **Reviewer pass before INTEGRATE.** Caught real P0 cross-task signature mismatches twice (5.1.3 backoff/unsubscribe gap; 5.4.2 stub-vs-real API drift) before they hit prod.
- **Pre-deploy migrations via Supabase MCP.** `apply_migration` ran 4 migrations against the linked staging DB before each batch deployed, eliminating the "code shipped before column exists" failure mode.
- **Hardware-permissive + processor-locked architecture (5.2.0).** Defense in depth at type, DB, and UI layers means the lock has no single failure point. Hardware drivers are pluggable on a compatibility matrix flip — no code change needed when Valor certs a new device.

## What surprised

- **`.env.local` doesn't load in Next 16 standalone mode.** First deploy looked successful but every admin-client call started failing silently because `pm2 reload` doesn't refresh the process env. Bare `} catch {}` in the login route swallowed the actual error for hours. Fix: `DEPLOY.sh` now sources `.env.local` before `pm2 reload --update-env`, and bare catches are now banned (login route logs).
- **Lint debt was 114 errors at session start.** 50 mechanical fixes via 2 parallel sub-agents; the other ~50 are real React 19 compiler bugs (refs/setState-in-effect/static-components) registered as `bucketBLintDebt` in eslint.config.mjs and parceled across V5/V6/V7 cleanup tasks (5.4.4, 6.7.4, 7.5.2, 7.5.3).
- **E2E tests against prod can't easily verify code that hasn't deployed yet.** Solved with the dev-only playwright config (5.5.3); a chicken-and-egg pattern that would have blocked every batch otherwise.
- **Cross-task stub coordination broke 5.4.2.** When an implementer creates stubs to keep their build passing in isolation, those stubs CAN drift from sister tasks' real APIs. Cycle 2 fix routed through the reviewer pattern caught it.
- **Smoke test race during pm2 reload.** First DEPLOY.sh false-failed because the smoke test fired in the 2-second window before the new worker was responding. Hardened to retry 5× × 5s with 2xx OR 3xx acceptance.

## What to do differently in V6+

1. **Cross-task interface contracts in the spec, not in the agent prompts.** When two sister tasks share a function signature (concurrency.ts, audit/log.ts), the spec file should declare the shape canonically. Reviewers should treat any drift as P0 immediately, not log it as P2.
2. **Auto-apply migrations as part of INTEGRATE.sh, not as a manual MCP step.** Risk: a migration that fails on prod data after passing locally; needs a dry-run or branched migration strategy first.
3. **Run e2e against a local dev server in INTEGRATE.sh, AND against prod in DEPLOY.sh.** Currently we only run prod-targeting tests pre-deploy, which means tests of new features always need a dev-server step. Splitting it eliminates the chicken-and-egg.
4. **The reviewer's "CONCERNS" verdict gate is too permissive.** Several P1 issues flagged as CONCERNS (custom PIN dialog vs canonical, hardcoded hex throughout offline UI) merged through. Tighten: P1 = FAIL unless the reviewer also writes a follow-up task ID into STATE.yaml.
5. **Don't use generic Tailwind colors in components even temporarily.** Adopt `bg-warning-bg`/`text-warning`/etc. tokens from the start instead of `bg-amber-100` — cheaper to do right than to clean up.
6. **Vitest config picks up Playwright spec files** — `npm test` currently fails before reaching unit tests. Fix in V7 reliability batch.
